# 구현 검증 기록

검증일: 2026-10-13. 이 문서는 자동·샘플 검증 결과와 아직 확인하지 못한 현장 조건을 구분합니다.

## 환경

### v0.1.3 배포 용량 축소

앱은 Whisper를 항상 CPU INT8로 실행하므로, 실행할 때마다 하던 float16→INT8 양자화를 모델 준비 단계에서 미리 수행해 저장합니다(`scripts/quantize_models.py`). small `model.bin`은 461→235 MiB, base는 138→72 MiB입니다. 실행 파일에서는 앱이 사용하지 않는 `hf_xet`, Pillow AVIF 코덱, sherpa-onnx 개발용 헤더·`.lib`을 제외했습니다. Pillow 자체는 reportlab이 import 시 요구하므로 유지합니다.

원본 float16 모델과 미리 양자화한 모델을 같은 `compute_type="int8"`로 불러와 base·small 모두 영어·한국어·중국어 샘플로 비교했습니다. 인코더 출력이 비트 단위로 같았고(최대 차이 0.0), 앱과 같은 전사 설정의 텍스트·avg_logprob·no_speech_prob·단어 타임스탬프와 확률이 모두 일치했습니다. 무작위 샘플링인 반복 재시도 설정(temperature 0.2)은 난수 시드를 고정한 상태에서 일치를 확인했습니다.

배포 ZIP은 약 715 MiB에서 419 MiB로, 압축 해제 크기는 약 969 MiB에서 659 MiB로 줄었습니다. 패키지 EXE의 `check_package.ps1 -CheckRuntime` 진단(파일 해시·모델·AEC·숨긴 UI·PDF)에 성공했고, 전사 4행·발화자 3행·MD 958바이트는 이전 패키지와 같았습니다. 같은 진단의 모델 로딩 시간은 2.05초에서 1.11초로 줄었습니다. 자동 테스트 55개가 통과했습니다.

### v0.1.2 개인 PC 이동용 패키지 보완

실제 빌드에 포함된 모듈과 런타임 의존성을 기준으로 44개 Python 구성 요소의 버전·라이선스 원문을 모았습니다. ONNX Runtime의 ThirdPartyNotices, PyAV/Pillow, Python/Tk, 모델·폰트, WebRTC/PortAudio, FFmpeg와 코덱 DLL 참고 고지를 포함해 142개 원문·출처 기록 파일을 보존합니다. 휠에 원문이 없는 항목은 해당 버전의 upstream 원문으로 보완했습니다. 실제 FFmpeg DLL 7개의 라이선스 문자열과 빌드 옵션·DLL 해시도 기록합니다. 개인 PC 간 이동용 고지·출처 정리이며 공개 배포를 위한 정확한 대응 소스 묶음이나 법적 적합성 판정을 완료했다는 뜻은 아닙니다.

오프라인 고지 수집·모델/원문 해시 검사·ZIP 생성·CRC 검사·ZIP SHA-256 기록을 빌드 절차에 추가했습니다. 배포 파일마다 해시를 담은 `PACKAGE_FILES.json`과 새 PC용 `check_package.ps1`도 포함합니다. 회의록·로그·설정·목록 외 모델 파일은 패키지 생성을 차단합니다.

별도 폴더에 실제 ZIP을 풀고 `check_package.ps1 -CheckRuntime`을 실행하여 파일 1,466개 검사와 EXE 자체의 로컬 모델·AEC·숨긴 UI·PDF 진단에 성공했습니다. 실제 마이크 녹음은 수행하지 않았습니다. 설치된 개발 Python으로 앱을 실행한 검사가 아니라 압축 해제한 EXE를 직접 실행한 검사입니다. 별도의 물리 PC에서는 아직 실행하지 않았으므로 그 PC의 장치·권한·호환성은 현장 확인이 남습니다.

### v0.1.2 비정상 반복 보호

길게 반복된 단어·구절·붙여 쓴 음절을 감지하고, 해당 음성 구간을 반복 억제 설정으로 한 번 재인식합니다. 재인식 실패·빈 결과·낮은 신뢰도·계속되는 반복은 `인식 확인 필요`로 표시하며 출처와 시간은 보존합니다. 함께 처리한 정상 전사 구간은 기존 결과를 유지합니다. 재인식은 정확성을 보장하지 않으므로 성공한 경우에도 상태에 `재인식`을 표시합니다.

반복 검출·정상 반복 보존·재시도 횟수 제한·정상 구간 보존·실패 시 화자 미배정·세션/MD/PDF의 확인 표시·대화 없는 로그를 자동 테스트합니다. 사용자 이미지에 나온 오류를 재현한 반복 텍스트를 모델 응답으로 주입해 보호 동작을 검증하며, 원본 음성은 확보하지 않았으므로 그 특정 음성에 대한 재인식 성공을 주장하지 않습니다.

자동 테스트 45개가 통과했습니다. 실제 small 모델에 재시도 설정을 적용한 파일 인식도 성공했습니다. 기존 한국어 합성 샘플의 정확도 우선 결과는 계속 정답과 일치했으며(공백·문장부호 제외), 계산 시간은 6.91초였습니다. UI의 주황색 확인 표시와 문서 출력도 확인했습니다. 이 검증에 실제 회의 대화는 사용하지 않았습니다.

### v0.1.1 인식 개선 검증

기본 모드를 small 모델·beam size 5·최대 12초 문맥의 정확도 우선으로 변경하고, base 모델 속도 우선도 선택할 수 있게 했습니다. 두 모드 모두 음성 감지 이전 버퍼를 0.2초에서 0.8초로 늘렸습니다.

`scripts/compare_recognition.py`는 같은 18.52초 한국어 SAPI 합성 샘플을 실시간 구간 생성기와 실제 로컬 인식 모델에 통과시킵니다. 기존 앞부분 버퍼에서는 첫 입력이 0.47초부터 시작해 `안녕하세요`가 `말씀하세요` 또는 `하세요`로 인식됐습니다. 수정 후에는 0초부터 입력해 첫 인사를 보존했습니다.

수정된 속도 우선에서는 `개발 일정`을 `개발 1점`으로 인식했고, 정확도 우선에서는 해당 문구를 포함한 샘플 전체가 정답과 일치했습니다(공백·문장부호 제외 문자 오류율: 속도 2.35%, 정확도 0%). 속도 모드의 계산 시간은 3.45초, 정확도 모드는 8.06초였으며 후자는 3개 구간으로 처리했습니다. 오디오를 모으는 시간·발화자 분석은 이 계산 시간에 포함하지 않습니다. 한 합성 샘플의 측정값이며 실제 동영상·회의의 정확도 수치로 일반화할 수 없습니다.

자동 테스트는 26개 통과했습니다. 늦은 음성 감지의 첫 음절 보존, 짧은 쉼에서 문맥 유지, 종료 시 짧은 발언 보존, 연속 발언의 구간 길이 제한, 정확도 모델 누락 시 자동 하향 대체하지 않음을 추가 검증했습니다. 비교 결과는 `output/recognition-comparison/comparison.json`에 있습니다.

정확도 모드의 두 입력 통합 샘플(한국어 MIC + 영어 SYSTEM, 언어 자동 감지)은 공통 시간축 20.52초를 21.95초에 처리했습니다. 오류·외부 통신 시도는 없었고 두 출처의 발화자와 MD·PDF를 생성했습니다. 이 CPU에서는 두 입력의 지속적인 동시 발언에서 정확도 모드의 지연이 누적될 수 있습니다. PC 출력 하나의 한국어 인식 비교와 구분해 해석해야 합니다.

아래는 v0.1.0 초기 검증 기록으로, base 기본값과 이전 구간 설정의 측정값을 보존한 것입니다.

Windows 11 x64, AMD Ryzen 5 5600G(논리 프로세서 12개), 사용 가능 메모리 약 13.9 GB. Python 3.12.13, CPU INT8 음성 인식. NVIDIA GPU를 사용하지 않았습니다. 모델·폰트는 별도 준비 도구에서 다운로드했고 검증 앱에는 오프라인 정책을 적용했습니다.

입력 라우팅 테스트는 가짜 장치와 처리기 경계의 데이터를 검사합니다. 실제 회의실 에코 제거 정확도를 의미하지 않습니다.

## 실제 로컬 모델 검증

`python scripts/verify_models.py`는 파일 기반으로 수행하며 물리 마이크를 열지 않습니다. 실행 시 앱의 네트워크 차단기가 기록한 시도는 0건이었습니다.

| 샘플 | 길이 | base 모델 처리 시간 | 확인 결과 |
| --- | --- | --- | --- |
| 공개 영어 JFK 샘플 | 11.00초 | 1.53초 | 영어 전사, 발화자 1명 |

한국어 base 결과에는 `개발 일정`을 `개발 1점`으로 인식한 오류가 있었습니다. small 모델에서는 이 문장을 올바르게 인식했습니다. 이 짧은 합성 음성 샘플만으로 한국어 정확도 또는 실제 참석자의 발화자 분류 정확도를 계산하지 않았습니다. 4명 샘플은 중국어이며, MIC와 SYSTEM 각각의 한국어 다인 회의를 검증한 결과가 아닙니다.

## 두 입력 통합 검증

`python scripts/verify_pipeline.py`는 한국어 현장 샘플과 영어 출력 샘플을 동시에 공급하며, MIC에 60ms 지연된 출력의 35% 크기 에코를 합성합니다. 물리 수집기만 대체하고 실제 AEC·음성 인식·발화자 분석·세션 저장·MD→PDF 변환을 사용했습니다. 샘플을 실제 시간보다 빠르게 공급했으므로 처리량을 측정하는 시험입니다.

- 공통 시간축 20.52초, 출력·마이크 두 스트림
- base 모델: 전체 13.47초, 음성 인식 구간별 약 1.30~1.47초, 발화자 분석 약 0.09~0.16초
- small 모델: 전체 약 35~38초로 입력 길이보다 오래 걸림
- MIC·SYSTEM 각각의 발화자 생성, 전사 8구간, JSON·MD·PDF 생성
- 오디오 보존 꺼짐에서 WAV 생성 없음
- 네트워크 차단기 기록 0건, 처리 오류 이벤트 없음

이 수치는 모델 준비·문서 생성도 포함한 파일 입력 처리량이며, 실제 회의에서의 발언→표시 지연이나 장시간 동시 발언 성능을 보장하지 않습니다. 기본 base 모델 선정의 근거로 사용했습니다.

## 장치·화면·문서

현재 PC에서 WASAPI 마이크 1개와 출력 장치 2개를 탐색했습니다. Realtek 출력 loopback을 약 2초간 실행해 10ms 기준 198프레임, 수집 버퍼 손실 0, 스트림 활성 상태와 종료를 확인했습니다. 이 시험은 마이크 수집을 수행하지 않았습니다. 무음 출력 스트림을 유지하여 PC 재생이 없을 때도 AEC용 loopback 참조가 이어지는 구성을 확인했습니다.

UI 예시의 이름 변경→MD·PDF 내보내기를 실행했고 화면 이미지와 PDF 렌더링 이미지를 확인했습니다. 이름, 한국어, 입력 출처, 페이지 배치가 표시됩니다. 긴 한국어 문서의 여러 페이지 생성과 텍스트 추출도 자동 검사했습니다.

최종 패키지 검증 결과는 `output/packaged-check-final.json`에 기록했습니다. Python 명령이 아닌 패키지 EXE를 직접 실행해 종료 코드 0을 확인했습니다. base 모델·AEC 로딩, 마이크 1개·출력 2개 탐색, 한국어 전사와 발화자 1명 분석이 성공했고 해당 진단은 6.83초 걸렸습니다. 이어 숨긴 예시 UI에서 전사 4행·발화자 3행과 MD 931바이트·PDF 62,079바이트 생성을 확인했습니다. 사용자 세션이나 마이크를 수집하지 않았습니다. 패키지 폴더는 약 503 MiB입니다.

## 남은 현장 검증

다음 항목은 실제 사용 환경에서 확인해야 합니다. 현재 결과를 이 조건에 대한 통과로 간주하지 않습니다.

1. 현장 2명 이상과 원격 2명 이상의 한국어 회의, 반복 발언의 ID 안정성과 오분류율
2. 실제 스피커·마이크의 거리, 잔향, 음량 변화, 겹친 발언, 클리핑에서 AEC 성능
3. 1시간 이상 실행, 회의 앱 동시 사용, 처리 지연과 메모리 사용량
4. USB·Bluetooth 장치 지연, 연결 해제·재선택, 다양한 샘플레이트
5. OS 방화벽 송신 차단 적용 및 외부 패킷 관찰. 현재의 Python 차단기 기록만으로 네이티브 DLL의 통신을 OS 수준에서 증명하지는 않음

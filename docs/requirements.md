# Standalone Meeting Transcriber — 구현 전 설계 원문

> 이 문서는 구현 전에 작성한 요구사항과 완료 기준을 보존한 기록입니다. 아래의 '현재 상태', '예정', '후보'는 작성 당시를 뜻합니다. 현재 동작은 상위 폴더의 readme.md와 docs/VALIDATION.md를 확인하세요.

온라인 회의에서 같은 공간에 있는 현장 참석자들과 온라인으로 연결된 원격 참석자들의 목소리를 PC 내부에서 텍스트로 변환하고, 발화자별로 구분해 실시간으로 보여주는 Windows 프로그램입니다. 사용 중 발화자 이름을 수정할 수 있으며, 다른 PC에서는 GitHub Releases에서 실행 패키지를 내려받아 사용하는 것을 목표로 합니다.

수정일: 2026-10-12

## 현재 상태

현재는 요구사항과 설계 문서 단계입니다. 이 폴더에 생성된 파일은 `readme.md`뿐이며 아래 기능은 구현 예정입니다. 프로그램 구현, 설치, 모델 다운로드, 녹음, GitHub 저장소 생성과 업로드는 수행하지 않았습니다.

## 1. 필수 기능

| 번호 | 요구사항 | 목표 동작 |
| --- | --- | --- |
| 1 | 현장·원격 참석자 목소리 전사 | 여러 현장 참석자의 마이크 입력과 여러 원격 참석자의 회의 앱 출력 오디오를 동시에 수집하여 한국어 텍스트로 변환 |
| 2 | 발화자별 구분 | MIC와 SYSTEM 양쪽 모두에서 각 참석자를 서로 다른 발화자로 구분 |
| 3 | 외부 데이터 전송 없음 | PC가 온라인 상태여도 전사 프로그램의 음성, 텍스트, 이름과 음성 특징을 외부로 보내지 않음 |
| 4 | 실시간 UI | 회의 중 전사 결과를 계속 표시하고 지연·발화자 분석 상태를 표시 |
| 5 | 사용 중 발화자 이름 수정 | 이름 변경을 해당 발화자의 기존·새 발언과 저장 결과에 반영 |
| 6 | 마이크의 스피커 재수음 제외 | PC 출력 오디오를 참조하는 로컬 에코 제거(AEC)를 적용하여 현장 발언을 보존하면서 마이크에 다시 들어온 스피커 소리를 억제 |
| 7 | 발화자 입력 출처 구분 | 발화자 목록·전사·저장 세션에서 각 발화자가 마이크(MIC) 또는 PC 출력(SYSTEM)에서 감지됐는지 표시 |
| 8 | Markdown 저장과 PDF 변환 | 정리된 전사 결과를 UTF-8 `.md`로 저장한 뒤 같은 내용을 로컬에서 `.pdf`로 변환 |

**실시간 전사, 발화자 구분과 스피커 재수음 억제는 첫 사용자용 버전의 필수 기능입니다.** 녹음만 하거나 회의 종료 후에만 전사하는 버전은 내부 검증에 사용할 수 있지만 완료 버전으로 간주하지 않습니다.

## 2. Windows 프로그램과 GitHub 배포

개인 사용 및 다른 PC에서 내려받아 사용하기 위한 배포입니다. 상용 판매나 서비스 운영을 전제로 하지 않습니다.

- 초기 지원 환경은 Windows 11 x64입니다.
- 소스 코드는 GitHub 저장소에 관리하고 사용자용 실행 패키지는 GitHub Releases에 배포합니다.
- 사용자는 릴리스 ZIP을 내려받아 압축을 풀고 Windows 실행 파일을 실행합니다.
- 사용자 PC에 Python이나 개발 도구를 별도로 설치하지 않는 폴더형 배포를 목표로 합니다.
- 음성 인식·발화자 모델은 재배포 조건을 확인해 동봉하거나 별도 모델 압축 파일로 제공합니다.
- 필요한 모든 자산을 준비한 뒤에는 프로그램이 네트워크에 접근하지 않습니다.
- 업데이트는 사용자가 GitHub에서 새 버전을 내려받는 방식입니다. 자동 업데이트 확인은 넣지 않습니다.

GitHub는 배포 파일을 받는 경로입니다. 회의 음성과 결과를 업로드하거나 처리하는 장소로 사용하지 않습니다. 실제 회의 데이터, 사용자 이름, 로그와 접근 토큰도 저장소나 릴리스에 포함하지 않습니다.

현재 저장소 주소, 릴리스와 실행 명령은 없습니다. 검증된 패키지를 만든 뒤 실제 다운로드·실행 방법을 추가합니다.

## 3. 오디오 수집과 로컬 처리

| 대상 | 수집 방법 | 입력 출처 |
| --- | --- | --- |
| 같은 공간의 현장 참석자 여러 명 | 선택한 마이크 입력 | MIC |
| 온라인으로 연결된 원격 참석자 여러 명 | 회의 앱 출력 장치의 WASAPI loopback | SYSTEM |

WASAPI loopback은 출력 오디오를 소프트웨어에서 직접 수집합니다. 상대방 소리를 스피커에서 마이크로 다시 받을 필요가 없으며 헤드셋에서도 사용할 수 있습니다. shared mode 출력 스트림의 수집은 [Microsoft 문서](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)를 기준으로 합니다.

회의 앱이 USB 헤드셋으로 소리를 출력하면 프로그램에서도 해당 헤드셋의 loopback을 선택해야 합니다. 두 스트림은 별도로 유지하고 공통 세션 시간 기준으로 처리합니다.

```text
마이크 원본 ────────────> 로컬 AEC ──> 처리된 MIC ──> 전사·발화자 분석 ─┐
                            ↑                                        │
출력 loopback ──┬─> 시간 정렬된 출력 참조                              │
                └─> SYSTEM 전사·발화자 분석(PC 출력 전사 켜기일 때) ────┤
                                                                     ↓
                           시간 정렬 + 세션 발화자 ID + 사용자 이름 매핑
                                                                     ↓
                                  실시간 UI / 로컬 세션 / MD 저장 → PDF
```

MIC와 SYSTEM은 입력 출처이며 사람의 신원을 뜻하지 않습니다. **마이크 한 개에도 여러 현장 참석자의 목소리가 들어오므로, 두 스트림 모두에 발화자 분석을 적용하는 것이 기본 동작입니다.** MIC 전체를 한 사람이나 `나`로 고정하거나 두 입력에 다른 라벨만 붙이는 것으로 요구사항 2를 충족하지 않습니다.

### 스피커 재수음 제외 로직

마이크 원본에는 현장 목소리와 스피커에서 나온 PC 음성이 함께 들어올 수 있습니다. 이미 마이크에 들어온 소리를 입력 장치 단계에서 선택적으로 수집하지 않는 것은 아니며, **수집 직후 AEC로 스피커 성분을 억제한 오디오만 MIC 전사·발화자 분석에 전달**하는 구조입니다.

1. 실제 스피커로 재생되는 출력 장치의 loopback을 에코 참조로 받습니다.
2. 참조와 마이크 입력의 샘플레이트·프레임 규격을 맞추고 버퍼 지연, 장치 시계 차이와 음향 전달 지연을 정렬합니다.
3. 로컬 AEC가 스피커→공간→마이크 경로의 변화를 추정하여 마이크 원본에서 에코 성분을 제거합니다. 잔여 에코 억제도 검토합니다.
4. 처리된 MIC에 음성 구간 검출, 전사와 현장 발화자 분석을 적용합니다. 원격 발언은 SYSTEM 쪽에서 전사합니다.
5. 현장과 원격이 동시에 말할 때에도 현장 발언을 보존하도록 처리합니다. PC에서 소리가 난다는 이유로 마이크 전체를 음소거하거나 해당 시간의 현장 발언을 버리지 않습니다.

로컬 AEC 후보는 WebRTC Audio Processing의 에코 제거 모듈이며, Windows용 네이티브 라이브러리와 Python 연결·배포를 검증한 뒤 확정합니다. 출력 참조를 역방향 스트림으로 전달하고 마이크 스트림을 처리하는 API 구조는 [공식 인터페이스](https://webrtc.googlesource.com/src/+/refs/heads/main/api/audio/audio_processing.h)를 참고합니다. WebRTC의 오디오 처리 모듈만 로컬에서 사용하며 네트워크 통화 기능을 도입하는 의미는 아닙니다.

**마이크 전사와 PC 출력 전사는 각각 켜고 끌 수 있게 합니다.** PC 출력 전사가 꺼져 있어도 마이크의 스피커 재수음 제외가 켜져 있으면 출력 참조 수집은 계속 필요합니다. 이 참조는 AEC용 메모리 버퍼에서만 사용하고 전사·발화자 분석·파일 저장 대상으로 보내지 않습니다. UI에는 `PC 출력 전사 꺼짐 / 에코 제거용 출력 참조 수집 중`으로 구분해 표시합니다.

마이크 전사가 꺼져 있으면 MIC 전사와 AEC용 마이크 수집을 중단합니다. 두 전사가 모두 꺼지면 수집을 중단합니다. 마이크 전사만 켜고 PC 출력 전사를 끈 모드에서도 AEC를 통해 현장 발언만 남기는 것을 목표로 합니다.

출력 참조를 받을 수 없거나 장치가 바뀌어 참조가 맞지 않으면 상태를 표시하고 참조 재연결·AEC 상태 초기화를 수행합니다. 이때 처리되지 않은 마이크 원본을 정상 처리 결과처럼 자동 전사하지 않고 MIC 전사를 일시 중단하며, 해당 구간의 처리 공백을 표시합니다.

스피커 재수음을 모든 환경에서 100% 제거한다고 보장하지 않습니다. 큰 음량, 마이크 입력 클리핑, 잔향과 장치 지연 변화에 따른 잔여 에코·현장 음성 손상을 평가해야 합니다. 참조에 없는 다른 기기의 스피커 소리는 이 방법의 제거 대상이 아닙니다. 전사문이 같다는 이유만으로 현장 발언을 자동 삭제하지 않습니다.

### 음성 인식 후보

`faster-whisper`와 로컬 다국어 모델을 사용합니다. CPU INT8을 출발점으로 검증하고 NVIDIA GPU 가속은 선택 사항으로 검토합니다. 모델 이름만 지정하면 자동 다운로드가 발생할 수 있으므로 실행 시 로컬 모델 경로를 사용합니다. [공식 저장소](https://github.com/SYSTRAN/faster-whisper)

한국어에는 영어 전용 모델을 사용하지 않습니다. 모델 크기와 설정은 회의 앱·음성 인식·발화자 분석을 함께 실행한 상태에서 결정합니다. 현재 성능은 측정하지 않았습니다.

### 발화자 구분 후보

`pyannote.audio`의 `speaker-diarization-community-1`을 로컬 발화자 구분 후보로 검토합니다. 해당 모델은 로컬 실행과 오프라인 사용을 지원합니다. [모델 안내](https://huggingface.co/pyannote/speaker-diarization-community-1)

이 후보를 곧바로 실시간 엔진으로 간주하지 않습니다. 오디오를 연속 구간으로 분석하고 음성 특징을 비교하여 구간이 달라도 같은 사람에게 같은 세션 ID를 부여하는 처리가 추가로 필요합니다. Windows 패키징, 지연과 ID 안정성을 검증한 뒤 최종 엔진을 확정합니다.

- MIC에서 여러 현장 참석자의 목소리를 분석하고, SYSTEM에서도 여러 원격 참석자의 목소리를 분석합니다.
- 양쪽 모두 새로운 목소리를 감지하면 `발화자 1`, `발화자 2` 등의 세션 ID를 만듭니다. 세션 ID는 두 입력 사이에서 충돌하지 않게 관리합니다.
- 입력 출처와 발화자 ID를 별도로 보존하고, 발화자 목록에도 `마이크(MIC)` 또는 `PC 출력(SYSTEM)`을 항상 표시합니다. MIC라는 이유로 `나`를 자동 지정하거나 현장 참석자들을 한 사람으로 묶지 않습니다.
- 정보가 부족하면 `발화자 확인 중`으로 표시하고 분석 결과에 따라 갱신합니다.
- 구간별 분석 결과를 세션 ID에 연결하며, 사용자 이름을 다른 사람에게 잘못 옮기지 않도록 변경 이력을 관리합니다.
- 실명은 사용자가 입력합니다. 음성만으로 참석자 실명을 자동으로 알아내는 기능은 요구하지 않습니다.

겹쳐 말하는 경우 발화자 구분과 전사 정확도가 낮아질 수 있습니다. 발화자 구분은 섞인 목소리를 완전히 분리하는 기능과 다릅니다. 겹친 발언은 상태를 표시하고 오분류된 개별 발언의 발화자를 수동으로 바꿀 수 있게 설계합니다.

## 4. 외부 전송 없는 실행 조건

온라인 PC에서도 **전사 프로그램과 하위 프로세스가 외부로 통신하지 않는 것**을 운영 기준으로 합니다.

- 음성, 텍스트, 이름, 음성 특징, 세션 정보와 로그를 로컬에서만 처리·저장합니다.
- 외부 전사 API, 클라우드 발화자 분석, 원격 오류 보고를 사용하지 않습니다.
- 자동 모델 다운로드, 원격 자산 로딩, 텔레메트리와 사용량 전송을 비활성화합니다.
- 필요한 모델이 없으면 안내하고 해당 처리를 중단합니다. 외부 서비스로 대체하지 않습니다.
- UI의 폰트·스크립트 등도 원격으로 불러오지 않습니다.
- 결과는 로컬 폴더에 저장합니다. 외부 전송을 원하지 않으면 OneDrive 등 자동 동기화 폴더를 저장 위치로 선택하지 않아야 합니다.

`pyannote.audio` 사용 시 선택적 텔레메트리를 끄기 위해 라이브러리 로딩 전에 `PYANNOTE_METRICS_ENABLED=0`을 설정합니다. 다른 의존성의 통신도 점검합니다. [공식 안내](https://github.com/pyannote/pyannote-audio#telemetry)

최초 배포 파일·모델 준비와 회의 전사는 분리합니다. 후보 발화자 모델의 최초 다운로드에는 제공처의 이용 조건 동의와 인증이 필요할 수 있습니다. 재배포 조건을 확인해 패키지 구성을 정하며, 개인 다운로드 토큰은 동봉하지 않습니다.

온라인 회의 앱은 통화 자체를 위해 음성을 전송합니다. 외부 전송 차단 범위는 **별도 전사 프로그램**입니다. 회의 앱까지 음성 전송을 막으면 온라인 음성 회의가 성립하지 않습니다.

검증 시 온라인 PC에서 프로그램과 하위 프로세스의 외부 연결 시도를 확인하고, 해당 프로세스의 외부 통신을 차단해도 필수 기능이 동작하는지 확인합니다. 현재는 구현 전이므로 외부 통신 없음이 검증된 상태가 아닙니다.

## 5. 실시간 UI와 이름 변경

| 화면 영역 | 기능 |
| --- | --- |
| 장치 설정 | 마이크·출력 장치 선택과 입력 레벨 |
| 회의 제어 | 시작, 일시정지, 종료, 마이크 전사·PC 출력 전사 각각 켜기/끄기 |
| 에코 제거 | 스피커 재수음 제외 기본 켜기, 출력 참조 수집 상태와 오류 표시 |
| 전사 목록 | 경과 시간, 마이크(MIC)·PC 출력(SYSTEM) 출처, 발화자 이름, 텍스트, 처리 상태와 자동 스크롤 |
| 발화자 목록 | 각 발화자의 세션 ID·표시 이름·입력 출처, 이름 편집과 해당 발화자의 발언 확인 |
| 상태 표시 | 모델 준비, 전사 지연, 발화자 분석 대기와 장치 오류 |
| 저장 | 로컬 세션 저장, Markdown 저장 후 PDF 생성, 파일·저장 폴더 열기와 PDF 재생성 |

텍스트가 준비됐지만 발화자 분석이 끝나지 않았다면 텍스트를 먼저 표시하고 발화자 라벨을 나중에 갱신합니다. 처리 중인 결과와 확정 결과를 구별합니다.

발언 후 수 초 수준의 지연으로 읽을 수 있는 텍스트를 보여주는 것이 설계 목표이며 보장 수치는 아닙니다. 발화자 확정에는 더 긴 관찰 구간이 필요할 수 있으므로 전사 표시 지연과 발화자 확정 지연을 각각 측정합니다.

### 이름 변경 규칙

1. 사용자가 회의 중 `발화자 1`을 선택해 `김대리`로 변경합니다.
2. 같은 세션 ID의 이전 발언과 이후 발언에 모두 `김대리`가 표시됩니다.
3. 저장 결과에도 최신 이름을 반영합니다. 이미 생성한 Markdown·PDF는 재저장·재생성할 때 최신 이름으로 갱신됩니다.
4. 이름을 다시 바꿔도 내부 ID는 유지하며 자동 분석이 사용자 이름을 기본 라벨로 덮어쓰지 않습니다.

이름은 `speaker_id → display_name` 매핑으로 관리합니다. 이름 변경은 같은 ID의 모든 발언에 적용하고, 오분류된 개별 발언은 발화자 재배정으로 수정합니다. 이름과 음성 특징의 자동 재사용 범위는 현재 회의 세션으로 한정합니다.

### 발화자별 입력 출처 표시

발화자 번호는 세션 전체에서 중복 없이 부여하고, 출처는 이름과 분리된 배지·열로 표시합니다. 이름을 수정해도 출처 표시는 유지합니다.

| 세션 발화자 ID 예시 | 초기 표시 이름 | 입력 출처 | 이름 변경 후 표시 예시 |
| --- | --- | --- | --- |
| speaker_0001 | 발화자 1 | 마이크(MIC) | 김대리 · 마이크(MIC) |
| speaker_0002 | 발화자 2 | 마이크(MIC) | 이과장 · 마이크(MIC) |
| speaker_0003 | 발화자 3 | PC 출력(SYSTEM) | 박팀장 · PC 출력(SYSTEM) |
| speaker_0004 | 발화자 4 | PC 출력(SYSTEM) | 발화자 4 · PC 출력(SYSTEM) |

세션의 발화자 레코드에 `speaker_id`, `display_name`, `source`를 저장하며, `source` 값은 `MIC` 또는 `SYSTEM`입니다. 각 전사 구간에도 실제 수집 출처를 별도로 보존합니다. 이름 변경·재분석·세션 재열기·내보내기에서 출처를 잃거나 이름으로 추정하지 않습니다.

발화자 재배정은 같은 입력 출처의 발화자 목록에서 수행하며, 음성 유사성만으로 MIC 발화자와 SYSTEM 발화자를 자동 합치지 않습니다. 에코 제거용 출력 참조만 수집하는 상태에서는 SYSTEM 발화자를 만들지 않습니다.

출처는 음성의 수집 경로를 뜻합니다. PC 출력에는 온라인 회의뿐 아니라 동영상 음성도 들어올 수 있으므로 UI의 기본 출처 표시는 `원격` 대신 `PC 출력`을 사용합니다. 아직 발화자가 확정되지 않은 구간도 `발화자 확인 중 · 마이크(MIC)`처럼 출처는 표시합니다.

회의 앱의 음소거 상태와 별도 프로그램의 마이크 수집 상태는 다릅니다. 회의 앱에서 음소거해도 전사 프로그램은 마이크를 받을 수 있으므로 수집 상태와 제어를 UI에 명확히 표시합니다.

## 6. 사용 흐름과 저장 결과

1. GitHub Releases에서 Windows 실행 패키지와 필요한 모델을 내려받아 준비합니다.
2. 프로그램을 열고 회의 앱과 같은 마이크·출력 장치를 선택해 레벨을 확인합니다.
3. 마이크 전사와 PC 출력 전사를 각각 선택합니다. 마이크 전사는 스피커 재수음 제외를 기본 적용하며, PC 출력 전사가 꺼져도 에코 제거용 출력 참조가 필요하면 이를 표시합니다.
4. 시작을 누르면 선택한 입력을 처리하고 회의 중 전사 결과를 표시합니다.
5. 현장·원격 참석자의 발화자 목록에서 사용자가 각 이름을 수정합니다.
6. 종료하면 남은 구간을 처리하고 최신 이름이 반영된 전사 결과를 Markdown으로 저장한 뒤 PDF를 생성합니다. 완료된 파일의 위치와 변환 상태를 화면에 표시합니다.

다음은 실제 녹음 결과가 아닌 표시 예시입니다.

```text
[00:00:08] [마이크/MIC] [발화자 1] 오늘은 일정과 진행 상황을 확인하겠습니다.
[00:00:13] [마이크/MIC] [김대리] 현장 검증은 금요일까지 마무리할 예정입니다.
[00:00:20] [PC 출력/SYSTEM] [발화자 3] 개발 결과도 함께 공유하겠습니다.
[00:00:25] [PC 출력/SYSTEM] [발화자 확인 중] 다음 주 일정을 확인해 주세요.
```

전사 구간에는 구간 ID, 시작·끝 시간, 입력 출처, 발화자 ID, 텍스트와 상태를 저장합니다. 세션에는 이름 매핑을 별도로 보존하고 Markdown·PDF의 표시 이름을 그 매핑으로 생성합니다. 오디오의 로컬 보존 여부는 사용자가 선택하며, MIC 보존에는 AEC 처리 후 오디오를 사용합니다. AEC 전 마이크 원본은 기본 저장하지 않습니다. PC 출력 전사가 꺼진 경우 AEC용 출력 참조도 저장하지 않습니다.

### Markdown 저장과 PDF 변환

기본 결과물은 `.md`와 그 문서에서 변환한 `.pdf`입니다. 사용자가 선택한 로컬 폴더에 같은 기본 파일명으로 저장합니다. 다음 경로는 구현 예정인 출력 예시입니다.

```text
선택한 저장 폴더/
  2026-10-12_143000_회의기록.md
  2026-10-12_143000_회의기록.pdf
```

- 회의 제목, 시작 시각(시간대 포함), 발화자 목록과 입력 출처, 경과 시간별 전사문을 포함합니다.
- 시간순으로 정렬하고 최신 발화자 이름을 적용합니다. `정리`는 문서 구조·줄바꿈 정리를 뜻하며 자동 요약이나 발언 내용 변경을 뜻하지 않습니다.
- 발화자 확인이 끝나지 않았거나 처리 공백이 있는 부분은 문서에도 표시합니다.
- Markdown 저장을 먼저 완료하고 저장된 Markdown에서 PDF를 생성하여 두 결과의 내용과 이름·출처를 일치시킵니다.
- 회의 종료 후 남은 전사·발화자 처리가 완료되면 자동 생성합니다. 사용 중 저장한 중간 결과는 생성 시각과 중간본 상태를 표시합니다.
- 이름이나 발화자 배정을 수정한 뒤에는 재저장·PDF 재생성으로 최신 결과를 반영합니다. 변환 중 수정된 내용은 다음 생성에 반영하고 현재 변환본과 섞지 않습니다.
- PDF는 로컬 렌더러로 변환하고 재배포 가능한 한국어 폰트를 동봉합니다. 외부 변환 사이트, 원격 폰트와 웹 자산을 사용하지 않습니다.
- PDF의 한국어 글꼴, 자동 줄바꿈과 페이지 나눔을 검증하고 텍스트 선택·검색이 가능한 문서로 생성합니다.
- PDF 변환은 UI와 오디오 처리를 막지 않는 작업으로 실행하며 진행·성공·실패 상태를 표시합니다.
- PDF 생성이 실패해도 이미 저장한 Markdown은 유지하고 실패 이유와 재시도 기능을 제공합니다. 기존 결과물은 새 파일 생성이 성공한 뒤 교체하며, 다른 회의 파일은 덮어쓰지 않습니다.

현재 실제 회의 전사문과 PDF는 생성하지 않았습니다. 위 내용은 프로그램 출력 기능의 요구사항이며 실행 코드와 PDF 렌더러는 구현·검증 예정입니다.

자동 회의 요약, 결정 사항·할 일 추출과 회의 서비스 로그인 연동은 현재 필수 범위에 포함하지 않습니다.

## 7. 구현 후보와 처리 조건

| 구성 | 후보·방향 |
| --- | --- |
| 개발 환경 | Python x64, 의존성 호환성을 검증한 버전 고정 |
| 오디오 수집 | PyAudioWPatch 기반 마이크·WASAPI loopback |
| 스피커 재수음 억제 | 로컬 WebRTC AEC 후보 + 출력 참조 정렬·잔여 에코 억제 |
| 음성 인식 | faster-whisper + 로컬 다국어 모델 |
| 발화자 구분 | MIC·SYSTEM 각각의 로컬 Community-1 후보 분석 + 구간 간 ID 연결 |
| 화면 | Tkinter 기반 Windows 데스크톱 UI |
| 문서 출력 | UTF-8 Markdown + 로컬 PDF 렌더러·동봉 한국어 폰트 |
| 배포 | PyInstaller 폴더형 ZIP, DLL·모델·라이선스 고지 포함 |

PyAudioWPatch의 loopback과 장치 탐색은 [공식 저장소](https://github.com/s0d3s/PyAudioWPatch)를 참고합니다. 기술과 버전은 Windows 실행, 품질, 실시간 성능과 배포 검증 후 확정합니다.

- 수집·음성 인식·발화자 분석·UI 작업을 분리해 수집과 이름 편집이 멈추지 않게 합니다.
- 장치 원래 규격으로 수집한 뒤 모델 입력에 맞춰 채널 변환과 리샘플링을 수행합니다.
- 두 입력의 공통 시간 기준을 유지하며 발언 시간순으로 표시합니다.
- 구간 경계의 문장 잘림, 중복과 발화자 ID 변경을 처리합니다.
- 처리 큐가 쌓이면 지연을 표시하고 버퍼 초과나 누락을 조용히 무시하지 않습니다.
- 일시정지 구간의 경과 시간을 유지하고 종료 시 남은 구간 처리 상태를 표시합니다.
- 장치 변경과 연결 해제를 감지해 안내하고 재선택·복구할 수 있게 합니다.

여러 현장 참석자가 함께 사용하는 회의실 마이크·스피커 환경을 기본 검증 시나리오에 포함합니다. AEC는 음성 인식과 발화자 분석보다 먼저 적용하고, 출력 장치·음량·마이크 위치 변경에 따른 적응 상태를 점검합니다. 기본 loopback은 같은 출력 장치의 알림·동영상 소리도 수집할 수 있습니다.

현장 발화자 구분은 마이크와의 거리, 잔향, 음량 차이와 겹친 발언이 있는 조건에서 별도로 평가합니다. 한 사람의 가까운 마이크 입력에서 얻은 결과를 여러 사람이 공유하는 마이크의 성능으로 간주하지 않습니다. 실시간 처리 성능도 두 스트림 모두에 발화자 분석을 적용한 상태로 측정합니다.

## 8. 개발 순서와 완료 기준

| 단계 | 구현·검증 |
| --- | --- |
| 1 | 두 입력의 연속 수집, 독립 전사 선택, 로컬 AEC·출력 참조 정렬과 로컬 음성 인식 |
| 2 | 실시간 UI, 처리 큐, 지연 표시와 종료 처리 |
| 3 | 여러 현장·원격 참석자의 발화자 구분, 구간 간 ID 유지와 라벨 갱신 |
| 4 | 발화자별 입력 출처 표시·보존, 이름 변경·발언 재배정, Markdown 저장과 로컬 PDF 변환 |
| 5 | 외부 통신 차단 검증, 실행 패키지, 다른 PC 검증과 GitHub Release 준비 |

첫 사용자용 버전은 다음 항목을 모두 검증해야 완료로 간주합니다.

- 같은 마이크를 사용하는 현장 참석자 두 명 이상과 원격 참석자 두 명 이상의 목소리가 모두 텍스트로 표시되고 각각 구분됩니다.
- 원격만 말하는 회의실 조건에서 SYSTEM 전사는 유지되고 MIC의 같은 발언·가짜 현장 발화자 생성이 억제되는지 평가합니다.
- 현장만 말하는 조건과 현장·원격 동시 발언 조건에서 AEC가 현장 목소리를 훼손하거나 누락시키는지 평가합니다.
- PC 출력 전사를 끈 상태에서도 AEC용 참조로 스피커 재수음을 억제하며, 참조가 전사·저장되지 않는지 검증합니다.
- 출력 참조 누락, 장치 변경, 음량·위치 변화와 클리핑에서 오류·처리 공백을 표시하고 원본 자동 전사로 우회하지 않는지 검증합니다.
- 같은 발화자의 반복 발언이 구간 경계를 넘어 같은 세션 ID로 연결됩니다. 실제 샘플에서 오분류도 평가합니다.
- 회의 중 결과가 갱신되고 발화자 분석이 늦어도 UI와 이름 편집이 멈추지 않습니다.
- 이름 수정이 기존·새 발언과 저장 결과에 일관되게 반영됩니다.
- 발화자 목록·각 전사 구간·Markdown·PDF에서 마이크와 PC 출력 출처가 구분되며, 이름 변경과 세션 재열기 후에도 유지됩니다.
- 회의 종료 시 Markdown과 동일한 내용의 PDF가 생성되고, 한국어·긴 발언·여러 페이지에서 글자 누락이나 잘림 없이 표시되며 텍스트 선택·검색이 가능합니다.
- PDF 변환 실패 시 Markdown을 보존하고 재시도할 수 있으며, 변환 과정에서도 UI가 응답하고 외부 통신이 발생하지 않습니다.
- 온라인 PC에서 외부 통신이 없고, 전사 프로그램의 외부 통신을 차단해도 필수 기능이 작동합니다.
- 장시간 회의, 동시 발언, 장치 연결 해제와 지연에서 오류와 데이터 손실 여부를 확인할 수 있습니다.
- Python이 없는 다른 Windows PC에서 GitHub 배포 패키지를 내려받아 실행할 수 있습니다.

현재는 위 항목의 속도·정확도·배포 호환성 검증 결과가 없습니다.
